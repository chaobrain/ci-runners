## 现有入口与后续改动

- `ci_runners/part.py` 与 `actions/part/action.yml`：保留本地 record、outcome、
  summary 及命令退出语义，在生成后发布 bundle。`uploaded` 仍表示发布成功。
- `ci_runners/artifacts.py`：复用 `members`、`current` 和既有名称、尝试规则。
  GitHub 路径保留 `newest`；内部路径先核验显式引用，再交给相同解析器。
- `ci_runners/verdict.py` 与 `actions/verdict/action.yml`：读取、补救和完整性
  错误接入内部后端，保持 `decide` 对 red 的优先级及缺结果的失败语义。
- `ci_runners/flow.py` 与 `actions/flow/action.yml`：plan 的发布、fetch 的
  `check_checkout`/`unpack_files`、retry 的结果读取、locate 的主机定位须逐项核对。
  locate 查询 GitHub job 元数据不是 artifact 数据传输，不应盲目删除。
- `.github/workflows/ci.yml`、`part.yml`：计划文件、二次上传、额外报告以及
  retry 前的下载必须与生产端成对切换。包括取消或 runner 丢失后的补救路径。
- `actions/salvage/action.yml`：目前下载失败可继续，并有最多 16 份补救上传；
  内部模式不得借此吞掉认证或校验错误，也不得遗留 GitHub 上传步骤。
- braincell `.github/ci_download_map.py`：当前选择未过期、main 分支、提交为
  HEAD 祖先的最新 test-map；存储迁移保留选择规则和无 map 的既有降级。
- brainspike `scripts/ci_impact.py` 及 workflow：P4 前逐项记录实际分支、祖先、
  多映射合并和缺失降级规则；整个 Nightly 的失败不能代替映射有效性判断。
  这两个消费仓库本轮均不改动。

## 负责人需确认的决策

1. 同意以 3090a 为候选存储端、3090b 为另一试点端，优先评估受限 SSH 网关。
   若不能隔离仓库与运行，改选有授权边界的内部对象服务；不直接降级为全互信。
2. 明确网关授权签发方、独立服务身份、密钥生命周期和吊销方式。
   专用 CI 账户不等于仓库隔离；同账户任务不能持有跨仓库通用凭据。
3. 确认草案的接口、配置键、限额、超时、重跑引用、salvage 修订协议和版本策略。
4. 确认存储容量上限、监控、备份、单点故障责任，以及可信 brainmass CPU 试点。
5. 确认保留期限及跨运行映射的依赖保护办法；TTL 默认只输出候选，不删除。

## 部署 dry-run 交付格式

已细化的候选方案见 [P1 受限文件通道试点部署方案](storage-p1-deployment.md)。
它区分协议/实现/具体系统变更三道门槛；当前尚无可部署的网关构件。

这是一份待填写的部署计划，不是已执行的 `setup/plan.sh` 输出。现有
`setup/plan.sh ROLE` 只支持已有主机资源，不支持本草案的存储配置。
P1 部署批准前，应在私有证据目录保存以下资料，再提交脱敏摘要供评审：

- 两端的现有通道、专用键、forced command 与目录权限只读核查结果；
  每条连接标记“未查 / 认证失败 / 认证成功 / 授权通过”，不以端口可达代替授权。
- 存储根、临时区和完成区的拟建目录、所有者、权限、容量与配额；
  不使用现有模型、数据集目录，不修改既有 SSH 键或服务。
- 拟增密钥与 authorized_keys 限制、固定入口和请求校验策略；
  列出每个文件变更的 before/after、撤回办法及影响范围。
- 新服务、定时器、目录和权限变更逐项列为 Needs the lead；
  只有批准的具体计划可以 apply。私有清单、密钥及真实路径不随 PR 提交。
- 按 design 中的角色范围分别列出允许与拒绝的操作；客户端与服务端都
  运行负向检查。共享账户与公开 fork 不装内部凭据。

## 分阶段验收证据

P0 的完成标准是设计可评审，不代表负责人已确认协议或现场检查通过。
P1 经部署授权后保存小文件、大文件、并发、断线、超时、摘要一致性及越权
拒绝证据；在两台主机直接传输，不通过维护者电脑中转。缺少真实证据则停在 P1。

### 只读现场核对 2026-11-24

维护者提供的电脑端 SSH 身份已在 3090a、3090b、6000pro、h100 四个角色上
成功登录。该身份仅用于维护核对，未复制到 runner，未开启 agent forwarding。
具体地址、账户、路径、SSH 配置和原始 JSON 证据保存在仓库外的私有记录中。

本次核对区分了以下三种能力，不能相互替代：

- 十二个跨机方向的 SSH 端口探测全部成功。使用默认 SSH 身份与严格主机密钥
  校验时，六个方向认证被拒绝，另外六个方向因缺少受信任主机密钥而停止。
  没有关闭校验、补写 known_hosts 或用维护者电脑中转文件。
- 使用现有 pool 配置与专用 probe key，十二个方向中十一个返回状态 JSON；
  h100 到 6000pro 的一次受限 probe 连接被拒绝。3090a 与 3090b 的双向
  probe 均成功。现有认证通道确实存在，但其 forced command 只提供状态，
  不能视作文件操作或仓库/运行授权已经通过验收。
- 已有 org-sync 和 pool-probe 入口不扩权、不改用途。本次没有运行同步写入、
  上传下载、原子发布或越权文件测试，因此 P1 文件通道尚未验收。

存储路径核对发现：候选存储端的大盘挂载根允许所有本机账户写入，且未设置
sticky bit。在这样的父目录直接创建一个 mode 0700 的服务目录，仍不能保护
路径免受重命名或替换。不能直接采用该路径作为可信服务根，也不能为此擅自
改变共享挂载根权限。后续应由管理员提供受保护的路径命名空间或根目录保护的
挂载入口；另一个可评审选项是以根文件系统的受保护专用目录做限额小试点。
两种选项都须核对完整父路径、所有者与存储配额，具体路径只留在私有部署计划。

候选存储端的 `sudo -n -l` 要求密码，本轮未证明具备可用的非交互管理员权限。
未修改账户、密钥、authorized_keys、服务、定时器、目录或权限，也未移动标签。
下一道部署评审需同时确定协议/签发方、独立服务身份和安全路径，再批准具体
系统变更。本记录不能替代 `setup/plan.sh` 的真实输出或完整传输验收。

P2 为发布、读取、列举、尝试引用、补救和错误分类添加契约及回归测试，
对去掉身份检查、允许旧尝试、跳过摘要、忽略完成标记、放宽安全解包等关键
行做变异测试。至少证明跨仓库、跨 run、跨 run_attempt、跨 part_attempt
串读会失败。上传后丢响应、并发冲突与清理竞争也需覆盖。

P3 只切一个可信 brainmass CPU 工作流。保存同一提交的依赖与硬件信息、
收集/通过/失败/跳过数、时长、manifest 与传输字节；逐项复现命令失败、
发布失败、读取失败和 failed-jobs 重跑。内部临时文件路径不能调用 GitHub
artifact 上传。GPU/队列不可用单独记录，不计通过。

P4 先 braincell 再 brainspike，连同项目专用读取脚本，验证 CPU、GPU、
完整 Nightly、一次重跑和多映射读取再推广。文档包已独立实施的策略不重做。
P5 先审查 TTL dry-run，再授权清理，观测 7 天生成字节、驻留时间及实际磁盘
占用。压缩传输字节与磁盘占用分别统计，不承诺固定容量收益。

## 回滚与停止

出现越权、校验失败、旧结果串读或判定变化即停止推广。保留对象及日志，
不自动清空目录。保存旧版本引用与后端配置，等待在途运行完成或明确作废后，
仅对新运行切换后端；已开始的运行不跨后端读取。配额耗尽时回退 GitHub
可能仍不可用，此时暂停受影响任务并保留证据；付费或账单变更另行决定。
